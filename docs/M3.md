# M3 增强：只听指定 App、会议模式回声消除

> 2026-11-26 · 这次只做这两项；术语表、本地识别模型、Windows 版暂缓

## 只听指定 App 的声音

**用法**：

- 「听」选了电脑声音或会议时，下方会多一个「来自」选择器，默认是「所有电脑声音」，可以改成某个软件（例如腾讯会议、Chrome）。
- 选择器在三个地方都有：引导页、运行时的顶栏、设置 → 通用。
- 列表只包含用过声音的软件，正在播放的排在前面，并显示"正在播放"。

**实现**：

- 辅助程序 `audio-tap --list-apps` 枚举 Core Audio 的进程对象，用"责任进程"（`responsibility_get_pid_responsible_for_pid`）把辅助进程归到所属的 App。例如 Chrome 的 Helper 进程、从终端启动的 `say`（归到终端）。
- `audio-tap --app <bundleID>` 只采集属于这个 App 的进程，用的是 `CATapDescription(monoMixdownOfProcesses:)`。
- 录音过程中，通过监听系统的进程列表变化来动态更新 Tap 的进程列表（`kAudioTapPropertyDescription` 支持修改），另每 2 秒兜底检查一次。

**实测**：

| 场景 | 结果 |
|---|---|
| 只听 Ghostty，录音开始 3 秒后用 `say` 播放 | ✅ 新进程出现后 10ms 内加入 Tap，第一句完整录到 |
| 只听 Chrome（有 3 个音频进程但没在播放），同时播放 `say` | ✅ 完全静音（-120dB） |
| 目标 App 没在运行 / 没有音频进程 | ✅ 照常开始，录到静音；进程出现后自动加入 |

## 会议模式回声消除

**用法**：设置 → 通用 → 「会议模式回声消除」，默认开启，只在会议模式下生效。

**实现**：

- 会议模式下，"我"这一路改由辅助程序用 macOS 的 Voice Processing 音频单元（`kAudioUnitSubType_VoiceProcessingIO`）采集。
- 只取处理后的单声道人声；输出端送静音，回声消除以扬声器实际播放的声音为参考，所以其他软件播放的声音也能被消掉。
- 先启动麦克风，再启动电脑声音录音。
- 回声消除启动失败时，自动改用普通麦克风采集。
- 文字层面的回声去重（M2）继续保留，作为兜底。

**踩坑记录**：

1. **AVAudioEngine 开启回声消除后无法启动**：开启后麦克风格式变成 48kHz×**9 声道**，`engine.start()` 报 -10875（初始化失败）。试过接静音混音器、`prepare`、不改 ducking、tap 不指定格式，全部失败。最后绕开 AVAudioEngine，直接用底层音频单元，指定输出单声道，解决。
2. **会压低其他软件的音量（ducking）**：已经设为最小档（`kAUVoiceIOProperty_OtherAudioDuckingConfiguration`，min）。实测"对方"录音的最响段仍从 -14.6dB 降到 -22.6dB，约低 8dB。这是系统在混音阶段做的，**你听到的会议声音也会变小**。macOS 上没有接口能彻底关闭（旧的 `DuckNonVoiceAudio` 只在 iOS 上有）。对识别没有影响，录音内容完整、采样率不变（每秒稳定 48000 帧）。
3. **启动多花约 1.5 秒**：回声消除初始化比较慢。

**还没验证的**：

- 实际消除回声的效果。开发机扬声器是静音的，测不了，需要在真实会议里外放测试。
- 回声消除固定使用系统默认的麦克风和扬声器，设置里选的麦克风设备在会议模式下不生效。
