## 实测延迟（真实服务，从说完一句开始计时）

**实时抓电脑声音，VAD 停顿 600ms**，5 句中英混合会议发言：

| 指标 | 平均 | 中位 | P90 | 目标 |
|---|---|---|---|---|
| 说话时出临时文字 | 边说边出 | | | ≤ 0.5s ✅ |
| 原文确定 | 1022 ms | 936 ms | 1307 ms | ≤ 0.8s ⚠️ |
| 译文开始出现 | 1261 ms | 1221 ms | 1455 ms | ≤ 1.5s ✅ |
| 译文完成 | 1415 ms | 1368 ms | 1636 ms | — |

**调参对比**（同一段 22.5 秒测试音频，按实时速度回放，各跑一次，有网络抖动）：

| VAD 停顿阈值 | 服务端 max_sentence_silence | 原文确定（中位） | 译文首字（中位） | 备注 |
|---|---|---|---|---|
| 600ms | 默认 800 | 968 ms | 1287 ms | 句中 400ms 停顿不切 |
| 500ms | 默认 800 | 1008 ms | 1296 ms | |
| 400ms | 默认 800 | 770 ms | 992 ms | 句中 400ms 停顿会被切开 |
| 600ms | 400 | 981 ms | 1272 ms | 调服务端参数基本无效 |
| 600ms | 300 | 1027 ms | 1171 ms | 同上 |

**结论**：

- 延迟主要由两部分组成：我们 VAD 的停顿阈值，加上 finish-task 之后百炼返回最终结果的约 250ms。
- 调低服务端的 `max_sentence_silence` 没有明显效果。
- M1 的"断句停顿时长"默认定 **500ms**，设置里可以在 300–1000ms 之间调。
- 后续可选优化（M2）：VAD 一判定说完，就先用最后一条临时结果开始翻译，省掉等最终结果的约 250ms；如果最终结果和临时结果不一致（标点除外），再重新翻译。

## M0 中发现并解决的问题

1. **没有声音播放时，系统不送任何数据**。最后一句说完后没有后续的静音帧，VAD 永远等不到停顿，这句就无法断句。
   **解决**：audio-tap 超过 150ms 没收到回调时，按实际流逝的时间补零，保证输出的时间轴是连续的。
2. **终端里抓不到电脑声音**。Ghostty 的 Info.plist 没有 `NSAudioCaptureUsageDescription`，从终端启动只能拿到全零数据。
   **解决**：必须以 App 的身份运行，这正好就是 M1 的形态。开发时用 `scripts/run-dev-app.sh`。
3. **权限查询不可靠**。临时签名的 App 重新签名后第一次 `TCCAccessPreflight` 会返回 undetermined，之后恢复正常，实际采集一直不受影响。
   **影响**：M1 不能把这个查询结果当作开关，要以实际收到的音量来判断，并且尽早改用固定的自签名证书。
4. **麦克风授权会阻塞**。等待授权弹窗时，cpal 打开设备的调用会一直挂起。
   **影响**：M1 的界面要在开始采集前提示用户授权，并且不能阻塞主线程。

## 关键设计（已同步到 PLAN.md）

- **一句话一个识别任务**：VAD 判断开始说话 → `run-task`（并补发 300ms 预缓冲）→ 推送音频 → VAD 断句 → `finish-task` → 拿到最终结果。连接复用，静音不计费。
- **默认模型**：识别用 `qwen-audio-3.1-asr-flash-streaming`，翻译用 `qwen-flash`（百炼 OpenAI 兼容模式，支持 system 提示词和上文）。
- **audio-tap 输出**：f32le 单声道、原生采样率，静音补零；重采样统一在 Rust 端完成。

```bash

# 单元测试 + 集成测试（模拟的百炼 WebSocket 服务、端到端流水线）
```

## 其他发现

- 用业务空间专属 Key（`sk-ws-` 开头）时，识别和翻译都要用业务空间专属地址：`wss://<空间>.cn-beijing.maas.aliyuncs.com/api-ws/v1/inference` 和 `https://<空间>.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`。
- `/compatible-mode/v1/models` 的列表里没有流式识别模型，但它们实际可以调用。所以 M1 的"测试连接"不能靠这个列表判断模型是否可用，要实际发一次识别请求。
