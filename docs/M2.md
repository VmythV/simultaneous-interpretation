## 做了什么

| 功能 | 说明 |
|---|---|
| 会议模式 | 「听」多了第三个选项「会议」，同时采集麦克风（我）和电脑声音（对方），记录里用「我 / 对方」标签区分，顶栏显示两路音量 |

| 鼠标穿透 | 开启后点击会穿过字幕，落到下面的窗口；用快捷键、菜单栏或设置关闭 |
| 菜单栏图标 | 开始/停止、切换音源、字幕开关、鼠标穿透、打开主窗口、历史记录、设置、退出；正在听时图标变为实心 |
| 全局快捷键 | 默认 ⌃⌥S 开始/停止、⌃⌥Z 字幕、⌃⌥X 鼠标穿透，可在设置里录制修改；注册失败（被其他软件占用）会提示 |
| 历史记录 | 每次「开始 → 停止」保存一份（可在设置里关闭），历史窗口可查看、复制、导出、删除 |
| 导出 | TXT / Markdown / SRT，主窗口导出当前内容，历史窗口导出单条记录 |
| 关闭主窗口 | 改为隐藏，软件继续在菜单栏运行，字幕照常显示；点 Dock 图标重新打开，退出用菜单栏或 ⌘Q |

## 设计取舍

- **回声去重的判断规则**：
  - 两句去掉标点后的编辑距离相似度 ≥ 80%，判定为同一句；
  - 或者短的一句被长的一句包含：短句至少 6 个字，且不少于长句的一半长度。这样对方说一句「好的谢谢」，不会把我的一整句长话吞掉；
  - 在翻译调度器里统一判断，所以关闭翻译时去重也照样生效；
  - 如果"我"的那一句先出来，它会先显示，等对方那句到了再被移除，会闪一下。戴耳机就不会有这个问题。
- **窗口状态和用户设置分开存**：
  - 字幕的位置、大小、是否显示由后端保存在 `ui-state.json`，不放进 `settings.json`；
  - 这样设置窗口保存时，不会把刚拖好的字幕位置覆盖掉。
- **历史用 JSON 文件，不用 SQLite**：
  - 每次会话一个 `history/<开始时间>.json`，另有 `index.json` 存列表摘要；
  - 每 3 秒落盘一次，停止和退出时也会落盘；
  - 自用场景数据量小，不需要多引入一个数据库。
- **开始/停止统一交给主窗口**：菜单栏、快捷键触发的开始/停止都转交主窗口执行，所以权限检查（麦克风 / 系统录音）只有一套。

## 抢先翻译：实测后默认关闭

思路是 VAD 一判定说完，就用最后一条临时结果开始翻译，省掉等最终结果的约 250ms。

用同一段 22.5 秒的测试音频、真实百炼服务对比：

| | 原文确定（中位） | 译文首字（中位） |
|---|---|---|
| 抢先翻译开启 | 819 ms | 1113 ms |
| 抢先翻译关闭 | 832 ms | 1087 ms |

没有收益，原因如下：

- VAD 判定说完的那一刻，百炼的临时结果常常还差最后一两个字（比如"…公园散步" → 最终"…公园散步吧。"）。
- 最终结果一变就要取消、重新翻译，多花一次请求，界面上的译文还会闪一下。
- 6 句里只有 1 句的临时结果与最终结果一致，那一句快了约 300ms。

处理：代码保留（`PipelineConfig.speculative`，命令行 `run --speculative`），桌面应用默认关闭。

## 翻译连接预热

每次开始时先请求一次翻译服务的 `/models`（不计费），提前完成 TLS 握手。

实测第一句的「请求首字」从偶发的 1.4 秒降到约 360ms。
